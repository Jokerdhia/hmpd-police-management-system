HMPD POLICE MANAGEMENT SYSTEM — V2.0.0
======================================

Objectif
--------
Rendre le bot + dashboard plus stable, plus léger et mieux adapté à Render/Neon,
sans casser les fonctionnalités existantes.

Principales améliorations V2
----------------------------
- Pool PostgreSQL unique partagé entre le bot et le dashboard.
- Timeout SQL configurable (15 s par défaut) pour éviter les requêtes bloquées.
- Leaderboard réutilisant le cache enrichi des policiers au lieu de refaire les appels Discord.
- Cache Discord/officiers conservé et invalidé uniquement lorsque nécessaire.
- SSE temps réel renforcé avec nettoyage des connexions mortes et arrêt propre au redéploiement.
- Temps réel étendu aux notes MDT et sanctions.
- Protection anti double-action pour POST/PUT/PATCH/DELETE.
- Support optionnel de l'en-tête Idempotency-Key.
- Nettoyage de la mémoire de déduplication par timer unique.
- Health-check /api/health enrichi : PostgreSQL, latence DB, clients SSE, version, uptime.
- Fermeture propre du pool PostgreSQL et des clients SSE à l'arrêt Render.
- Index PostgreSQL V1.2 conservés pour points, présence, notes et sanctions.
- Pagination/recherche côté interface conservées.
- Polling de secours conservé, avec priorité au temps réel SSE.
- Aucun secret .env inclus dans le ZIP de release.

Variables optionnelles V2
-------------------------
DATABASE_POOL_MAX=10
DATABASE_STATEMENT_TIMEOUT_MS=15000
OFFICERS_CACHE_TTL_MS=15000
DISCORD_MEMBER_CACHE_TTL_MS=300000
AUTH_MEMBER_CACHE_TTL_MS=30000
ROLE_SYNC_INTERVAL_MS=60000
ACTION_DEDUPE_MS=3000

Déploiement
-----------
1. Conserver les variables d'environnement déjà présentes sur Render.
2. Remplacer les fichiers du repository par ceux de cette release.
3. git add .
4. git commit -m "HMPD v2 production upgrade"
5. git push

Contrôles effectués
-------------------
- Vérification syntaxique Node sur les fichiers backend critiques : OK.
- Vérification syntaxique du JS dashboard : OK.
- package.json / package-lock.json passés en version 2.0.0.
- Release nettoyée : pas de .env, node_modules, .git ou base SQLite locale.

Remarque
--------
Les tests réels Discord/OAuth/Neon nécessitent les secrets et services du déploiement Render.
